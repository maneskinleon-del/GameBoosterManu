## 🔧 Problema principal

**Perfil manual no se reaplicaba al reabrir el juego, y el boost quedaba activo al cerrarlo.**

Escenario del usuario:
1. Seleccionar perfil EXTREME manualmente (sin juego activo)
2. Abrir Free Fire → EXTREME debería aplicarse automáticamente
3. Cerrar Free Fire → boost, power mode, overlay y notificación deberían apagarse
4. Reabrir Free Fire → EXTREME debería reaplicarse solo

**Resultado antes del fix:**
- Paso 2: ✅ funcionaba (si el juego ya estaba corriendo)
- Paso 3: ❌ boost quedaba activo con el override manual
- Paso 4: ❌ no reaplicaba el perfil guardado

---

## 🛠️ Fixes implementados

### Fix A — Apagar boost al cerrar juego (SIEMPRE)

**Archivo:** `GameSessionManager.kt` → `triggerExitWithHysteresis()`

**Problema:** Cuando el usuario seleccionaba un perfil manualmente, `manualOverrideActive = true` bloqueaba la salida del boost al cerrar el juego. El boost, power mode, overlay y notificación quedaban activos indefinidamente.

**Solución:** Separar "recordar perfil manual" de "apagar boost en salida". El boost SIEMPRE se apaga al salir del juego, independientemente de si hubo selección manual.

```kotlin
// ANTES (bug):
if (manualOverrideActive) return  // ← bloqueaba toda la salida

// DESPUÉS (fix):
// manualOverrideActive NO se verifica aquí
// SIEMPRE ejecutar power mode OFF + overlay hide
```

### Fix B1 — Reapply de perfil manual al reabrir juego

**Archivos:** `GameSessionManager.kt`, `PreferenceManager.kt`

**Problema:** Al cerrar el juego, el perfil manual se borraba. Al reabrir, no había nada que reaplicar.

**Solución:**
1. `setLastManualProfile(context, package, profileId)` guarda el perfil en SharedPreferences con clave `last_manual_profile_<package>`
2. `getLastManualProfile(context, package)` lo recupera
3. `clearLastManualProfile(context, package)` lo borra después de re-aplicar
4. En `simulateGameLaunchInternal`, antes de la auto-detección, se verifica si hay un perfil manual recordado para ese package
5. **Fallback global:** si no hay clave per-package, se busca `last_manual_profile_` (clave global sin package) — esto cubre el caso de selección manual sin juego activo

```kotlin
// En simulateGameLaunchInternal:
val remembered = PreferenceManager.getLastManualProfile(context, packageName)
    ?: PreferenceManager.getLastManualProfile(context, "")  // fallback global
if (remembered != null || manualOverrideActive) {
    val profileToApply = remembered ?: currentProfileId ?: "extreme"
    setActiveProfile(profileToApply, isManual = true)
    applyBoostInternal(profileToApply, packageName)
    return
}
```

### Fix B2 — Persistir perfil al seleccionar manualmente (sin juego)

**Archivo:** `GameSessionManager.kt` → `setActiveProfile(isManual=true)`

**Problema:** Al seleccionar un perfil vía UI sin juego activo, `_simulatedGame.value` era `""`, por lo que la clave se guardaba como `last_manual_profile_` (global). Pero al reabrir el juego, `getLastManualProfile("com.dts.freefireth")` devolvía `null` porque la clave era diferente.

**Solución:** Al reabrir el juego, el reapply busca primero la clave per-package y luego la global como fallback. Esto cubre ambos flujos:
- Selección durante juego → `last_manual_profile_com.dts.freefireth=extreme`
- Selección sin juego → `last_manual_profile_=extreme` (global) → fallback la encuentra

### Fix C — Notificación neutral al ocultar overlay

**Archivo:** `GameBoostService.kt`

**Problema:** Al pulsar (x) en el overlay durante juego activo, la notificación quedaba mostrando el perfil activo sin contexto.

**Solución:** Cuando el overlay se oculta, se muestra una notificación neutral (sin perfil específico) que indica que el juego sigue activo pero el panel está oculto.

### Fix D — Solicitud de exención de batería

**Archivos:** `MainActivity.kt`, `AndroidManifest.xml`

**Problema:** En dispositivos Xiaomi/HyperOS, la optimización de batería mata GameBoostService cuando la app pasa a background.

**Solución:**
- Agregado permiso `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` en AndroidManifest
- Al iniciar la app, se solicita exención de optimización de batería
- Agregado a doze whitelist vía ADB: `dumpsys deviceidle whitelist +com.example`

### Fix E — Init timeout 10s → 30s

**Archivo:** `GameBoostRepository.kt`

**Problema:** En dispositivos lentos (Xiaomi Mi 10), el init del repository tardaba >10s. El `withTimeout(10_000)` lanzaba `TimeoutCancellationException`, el catch la silenciaba, y `GameDetector.start()` nunca se ejecutaba. Resultado: detección de juegos no funcionaba.

**Solución:** Aumentar timeout a 30s. El dispositivo real tarda ~15-20s en completar el init (DB + session manager + repo init).

## 🔑 Lecciones aprendidas

1. **Separar "recordar" de "actuar":** El perfil manual se recordaba, pero la acción de apagar boost dependía del mismo flag. Separar persistencia de comportamiento de salida.

2. **Fallback global en preferencias:** Cuando no hay package conocido (selección manual sin juego), una clave global permite recuperar el valor después.

3. **Init timeout en dispositivos lentos:** Un timeout de 10s puede ser insuficiente en hardware antiguo. El GameDetector nunca arranca si el init hace timeout.

4. **Guard clauses en `triggerExitWithHysteresis`:** El guard `if (oldGame != null || _fsmState.value == GAME_ACTIVE)` protege contra ejecución cuando nunca hubo juego activo.

5. **Observer de StateFlow solo dispara en cambios:** Ocultar el overlay con `hide()` no re-dispara `show()` porque `isBoostActive` no cambió de valor.
